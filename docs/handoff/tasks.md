## 1. URL 호출 점검 (해외 IP 차단 여부)

```
docs/research/자동 공지 감지 시스템 설계.md 의 §10 검증 실험 중 "실행 환경 IP 차단 여부"를 점검하려고 해.
목표: data/ 의 암장 데이터에서 공지 관련 http(s) 주소(contact.notice_url, 블로그 주소 등. instagram 과 네이버 카페는 제외)를 모아, 아래 두 환경에서 각각 한 번씩 요청해 결과를 표로 만든다.
 (a) GitHub Actions 실행기 (workflow_dispatch 로 수동 실행하는 워크플로)
 (b) Cloudflare Worker (일회성 점검용)
규칙:
 - 주소당 요청 1회, 식별 가능한 User-Agent(앱 이름과 연락처 URL), 요청 사이 간격 둠. 재시도로 차단을 우회하지 않는다. 403/429 면 그 호스트는 거기서 멈추고 기록만 한다.
 - 각 호스트의 robots.txt 도 한 번 읽어 공지 경로가 허용되는지 기록한다.
 - 결과 표: 주소, 호스트, 상태 코드, 응답 시간(ms), 본문 크기, 차단 의심 여부(403/429/캡차/빈 본문), 인코딩(UTF-8/EUC-KR), JS 렌더링 필요 의심 여부.
 - 결과는 docs/research/url-reachability.md 로 저장하고, 로컬 한국 IP 에서의 결과는 "참고용"이라고 따로 표시한다(실제 환경이 아니므로).
먼저 계획을 말해 줘. 구현은 내가 확인한 뒤에.
```

## 2. 38곳 공지 채널 조사

```
docs/research/자동 공지 감지 시스템 설계.md §3.1 에 따라, 암장 데이터(data/)에서 contact.notice_url 도 contact.instagram 도 없는 외벽(약 38곳)이 실제로 어디에 공지를 올리는지 조사해 표로 정리해 줘.
 - 각 외벽: 공식 홈페이지/시청·공단 공지/네이버 블로그/네이버 플레이스/네이버 카페/인스타그램/카카오 채널/기타 중 어디에 공지가 있는지, 가장 최근 공지 날짜, 근거 URL.
 - 공개 페이지만 본다. 로그인 필요, 차단된 페이지, 인스타그램 내부는 읽으려 하지 말고 "존재 여부(링크가 있는지)"만 기록한다. 모르면 "모름"으로 쓴다.
 - 결과는 docs/research/notice-channels.md 로 저장하고, 마지막에 채널별 개수 요약과 "자동 감지가 가능한 곳 / 링크 제보가 필요한 곳 / 모르는 곳"을 센다.
 - 사실이 불확실하면 추정하지 말고 표시해 줘. 내가 사람이 직접 확인할 것이다.
```

## 3. 주차 요금 계산 함수 + 데이터 변환

```
docs/prd/parking-info-display.md §3.1 을 읽고 요금 규칙(rate) 계산을 구현해 줘. 화면(카드)은 이 작업에서 건드리지 않는다.
 1) 순수 함수: (규칙, 분) → 금액 | 모름. 규칙 필드는 free_min, first{min,won}, step{min,won}, tiers[{upto,won}], day_flat, day_max. 시작한 단위는 올림.
 2) 테스트: §3.1 의 "검증용 계산 예시" 5곳(금곡공원, 서울산악문화체험센터, 영등포, 광교, 인천문학)의 3/5/8시간 값이 표와 같아야 한다. 경계값(무료 시간 직후, 상한 도달, 구간표 경계)도 추가.
 3) 데이터: 유료 외벽 10곳의 parking.fee 원문을 rate 규칙으로 변환해 data 에 추가(원문 fee 는 그대로 둔다). 변환한 곳마다 원문, 규칙, 계산된 3/5/8시간·하루 금액을 표로 보여 줘서 내가 원문과 대조할 수 있게 해 줘. 규칙으로 표현이 안 되는 곳은 억지로 변환하지 말고 따로 알려 줘.
먼저 기존 card-model.js 의 주차 로직과 테스트 형식을 읽고 계획을 말해 줘.
```

## 4. 주차 카드 한 줄 + 탭 + 주차장 길찾기 (3 이후)

```
docs/prd/parking-info-display.md 의 §3(카드 한 줄 위계), §4(탭 통로), §5(주차장 위치와 길찾기)를 구현해 줘.
 - 카드 한 줄: 상태 → 비용(현재 "최소 이용 시간" 필터 3/5/8시간 기준, 필터 없으면 3시간) → 위치. 값이 있는 것만. 기준 시간을 문구에 적는다.
 - 주차 줄 전체를 탭하면 외벽 시트 이용 탭의 주차 섹션으로 이동.
 - 상세 주차 섹션: 주차장 행마다 이름 + 메모 + 길찾기 아이콘. 기존 길찾기 앱 선택(기억) 방식을 재사용. 좌표가 없으면 지역+이름 검색으로 연다.
 - 상세에서 현재 필터 값에 해당하는 요금 행 강조.
선행 작업 3 이 끝났다고 가정한다. 먼저 계획과 바꿀 파일 목록을 말해 줘. 접근성(터치 44px, 색 외 표시)을 지켜 줘.
```

## 5. 공지 감지 MVP (1, 2 이후)

```
docs/research/자동 공지 감지 시스템 설계.md 와 docs/research/url-reachability.md, docs/research/notice-channels.md 를 읽고 공지 감지 MVP 의 spec 부터 써 줘 (구현은 spec 확인 뒤에).
원칙: 감지는 자동, 게시는 사람 승인. 자동으로 보여줄 수 있는 것은 "공지 있음 + 원문 링크 + 확인 시각" 까지. 휴관·시간·요금·suspended 값은 하루 1회 묶음 PR 로 제안만 하고 사람이 병합. checked_at 은 사람만 갱신.
MVP 범위는 보고서 §5 의 0~1단계(자체 사이트 게시판 새 글 감지 + 네이버 블로그 RSS)로 한정하고, 인스타그램은 링크 제보 방식(§3.1)만 다룬다.
spec 에는 사용자 스토리, 구현 결정, 테스트 결정(순수 파서와 diff 로직 중심), 범위 밖, 열린 질문을 넣어 줘. 실행 환경은 1번 점검 결과를 근거로 제안해 줘.
```

## 6. 퀵 태그 P0 (사용자 선행 작업 필요)

```
선행: 내가 구글 폼에 "태그" 단답형 항목을 추가하고 entry id 를 알려 준다.
docs/prd/post-log-quick-tags-spec.md 와 docs/prd/post-log-quick-tags.md §2~§5 를 읽고 P0 를 구현해 줘.
 - 순수 모듈: 태그 셀 해석(화이트리스트), 5번째 열이 없는 옛 시트 호환, 유효시간(혼잡 90분/날씨 3시간/지속 30일), 3건 미만 숨김.
 - 퀵 칩 시트와 카드의 태그 칩. config.quickTags 로 켜고 끈다(비면 요청·DOM 없음).
 - 혼잡도 질문을 저장 전에서 저장 후로 옮기되 설정으로 되돌릴 수 있게.
 - 기존 crowd.js 의 제보 제한(canReport)을 그대로 공유.
먼저 기존 crowd.js 테스트 형식을 읽고 seam 이 맞는지, 계획을 말해 줘. 큐레이션 Top 3 는 이 작업에 포함하지 않는다(그림자 모드로 먼저 수집).
```

## 7. 첫 사용 코치마크 (UI 확정 후)

```
docs/prd/post-log-quick-tags.md §9 를 읽고 코치마크를 구현해 줘.

 - 기존 첫 방문 안내 시트와 겹치지 않게 하고, ? 버튼에서 언제든 다시 볼 수 있게.
먼저 계획과 기존 첫 방문 안내(howto)와의 관계를 말해 줘.
```
