# PRD · 주차 정보 표시 개선

| 항목 | 내용 |
|---|---|
| 서비스 | 해벽 · haebyeok.app (인공외벽 모드) |
| 상태 | Draft v0.1 (2026-10-18) |
| 한 줄 요약 | 카드 한 줄에서 주차 결정(가능 여부·비용·어디)이 끝나게 하고, 더 알고 싶은 사람에게 상세로 가는 통로를 열며, 갱신 부담은 데이터 구조와 이용자 확인으로 줄인다. |

## 1. 배경: 이용자 피드백과 현재 상태

> "주차 가능여부나 협소 등 정보가 있어서 좋은데, 유료주차의 경우 주차비 안내도 있으면 좋을 것 같아요. 근데 주차정보는 변경될 수 있어서 끊임없이 업데이트가 필요하니 힘드실 것 같기도 하고 ㅋ"

데이터(`data/national.json`)와 코드를 확인한 결과는 다음과 같다. (2026-10-18 기준, 직접 집계)

| 사실 | 수치/내용 |
|---|---|
| 주차 상태 분포 (60곳) | 확인 필요(unknown) 32 · 무료 16 · 유료 10 · 불가 2 (주차 필드 없는 외벽 3) |
| 유료 10곳의 요금 정보 | 10곳 모두 `fee` 또는 안내 메모가 있음 |
| 카드 한 줄 | `주차 가능 · 외벽 앞`처럼 상태 + 외벽 자체 주차장만 표시. **요금은 이용 탭 안에만 있음** |
| 무료/유료 표기 | 코드 의도상 둘 다 "주차 가능"으로 읽게 하고 가격은 "요금" 줄에 둠 → 비용이 카드 첫 화면에서 보이지 않음 |
| 주차 줄의 탭 동작 | 없음. 상세는 `자세히 ›` → 이용 탭 → 주차 섹션까지 이동해야 함 |
| 확인일 | 외벽 하나당 `checked_at` 하나. 주차/요금 전용 확인일 없음 |
| 모두의주차장 언급 | 60곳 중 1곳(판교) |

**결론**: 요금 데이터는 이미 있는데 화면에서 눈에 띄지 않는 것이 문제의 핵심이다. 갱신 부담은 유료 10곳이면 감당 가능한 규모이고, 더 큰 손실은 "확인 필요" 32곳(53%)이다.

## 2. 목표 / 비목표

**목표**
1. 카드 한 줄만 보고 "차를 가져가도 되는지, 돈이 드는지, 어디에 대는지"를 알 수 있다.
2. 상세가 필요한 사람은 한 번 탭으로 주차 상세에 도달한다.
3. 주차 정보의 신선도를 이용자에게 정직하게 알리고, 갱신을 이용자 확인으로 일부 분담한다.

**비목표 (v1)**: 주차장 실시간 만차/잔여 대수 연동, 주차 예약·결제 기능, 제휴/수수료 기반 링크, 요금 자동 수집.

## 3. 카드 한 줄 위계

**원칙: 값이 있는 것만, 정해진 순서로 붙인다. 없는 필드는 자리를 채우지 않는다.**

> ① 상태(가능/불가) → ② 비용 → ③ 어디(외벽 자체 주차장 1곳) → ④ 바로 할 일(있을 때만)

| 데이터 상황 | 카드 한 줄 |
|---|---|
| 불가 | `주차 불가 · 주변 강남구견인차량보관소 노상주차장` (대안을 같은 줄에, 경고 톤) |
| 무료 | `주차 가능 · 무료 · 외벽 앞(협소)` |
| 유료, 요금 있음 | `주차 가능 · 유료 일 2,000원 · 외벽 앞` |
| 조건부 무료 | `주차 가능 · 4시간 무료 · 공원 주차장` |
| 유료인데 요금 모름 | `주차 가능 · 유료 · 요금 확인 필요` |
| 사전 구매 필요 | `주차 가능 · 일 4,000원 · 사전 구매` |
| 정보 없음 | `주차 정보 없어요 · 알려주기` (옅은 글씨, 전체가 모를 때만 한 번) |

- "가능"의 톤(긍정색)은 유지하고 **비용 토큰을 추가**한다. 무료와 유료를 구분해 보여준다.
- 긴 요금 원문은 한 줄에 넣지 않는다. 요금 형식이 외벽마다 다르므로(일 정액, 구간별, 기본+추가+상한, 무료 후 추가, 요일·시간 조건, 할인 혜택) 규칙을 하나의 틀로 정규화하지 않고, **모든 외벽에 같은 기준점의 금액**(§3.1)만 뽑아 비교한다. 원문은 상세에 둔다.

### 3.1 요금 규칙(`rate`)과 자동 계산

요금 형식이 외벽마다 다르지만(일 정액, 구간별, 기본+추가+상한, 무료 후 추가), **관찰된 형식은 몇 가지 규칙 조합으로 모두 표현된다.** 사람이 금액을 손으로 계산해 넣지 않고, **규칙만 입력하면 앱이 필요한 시간의 금액을 계산**한다.

| 규칙 필드 | 뜻 | 예 |
|---|---|---|
| `free_min` | 처음 무료 시간(분) | 영등포 240 |
| `first` | 첫 구간 `{min, won}` | 금곡공원 30분 400원 |
| `step` | 이후 추가 단위 `{min, won}` (시작한 단위는 올림) | 10분당 200원 |
| `tiers` | 구간표 `[{upto, won}]` (`first`/`step` 대신) | 광교 180분 이내 1,000원 · 360분 이내 2,000원 |
| `day_flat` | 시간과 무관한 일 정액 | 인천문학 2,000원 |
| `day_max` | 하루 상한 | 금곡공원 6,000원 |
| `conditions` | 금액을 바꾸는 조건 칩(계산에 쓰지 않음) | `주말·공휴일 무료`, `사전 구매`, `등록 필요`, `센터 이용 시 N시간 무료` |

- **계산 함수는 순수 함수** `분 → 금액 | 모름`이다. 무료 시간 → 첫 구간 → 추가 단위(올림) → 상한 순으로 적용한다.
- 카드 한 줄은 **현재 필터 값(3/5/8시간)**에 대한 금액을 보여준다. 필터가 없으면 3시간이 기본이며, 이 기본값은 임의 가정이라 상수로 두고 조정한다. 문구에 기준 시간을 항상 적는다(`5시간 기준 2,000원`).
- 같은 함수로 하루 종일 금액과 임의 시간(예: 상세의 시간 슬라이더)도 계산할 수 있다.
- 규칙으로 표현되지 않는 외벽은 숫자를 직접 넣는 `cost { h3, h5, h8, day }` **예외 필드**를 쓴다. `rate`가 있으면 `rate`가 우선한다.
- 모르는 값은 비워 둔다. `rate`가 없거나 계산이 불가능하면 요금 줄을 빼고 `요금 확인 필요`로 둔다. 추정해 채우지 않는다.
- 요약 문구는 계산 결과에서 자동으로 만든다: 무료 구간이 기준 시간 이상이면 `N시간 무료`, 아니면 `N시간 기준 N원`.
- 상세에는 계산된 3·5·8시간·하루 금액 표 + 원문 + 확인일을 모두 보여주고, 현재 필터 값에 해당하는 행을 강조한다(필터가 없으면 3시간 행).
- 입력 방식: 지금처럼 원문 요금을 알려 주면, **데이터를 넣는 시점에** 규칙으로 변환하고 계산된 3·5·8시간 금액을 원문과 대조해 확인한다. 앱이 실행 중에 문장을 해석하지는 않는다(자연어 파싱은 틀릴 수 있음).
- 가정과 한계:
  - "5분당"처럼 시작한 단위는 올림으로 계산한다. 실제 정산 방식이 다르면 외벽별로 확인해야 한다.
  - 요일·시간대에 따라 요금이 다른 곳(용인 평일 09~18시만 유료, 파주 주말·공휴일 무료)은 지금은 조건 칩으로 알리고 금액은 평일 기준으로 둔다. 보고 있는 날짜·시각에 맞춰 계산하는 것은 이후 과제다.
  - 손계산은 틀리기 쉽다는 것이 이 방식을 택한 이유다. 이 설계를 논의하는 중에도 5시간·8시간 금액을 손으로 계산한 예시 두 개가 틀렸다.

**검증용 계산 예시** (위 규칙으로 계산, 3 / 5 / 8시간)

| 외벽 | 규칙 | 3시간 | 5시간 | 8시간 |
|---|---|---|---|---|
| 금곡공원 | 첫 30분 400원, 10분당 200원, 일 최대 6,000원 | 3,400 | 5,800 | 6,000 |
| 서울산악문화체험센터 | 첫 5분 150원, 5분당 150원, 일 최대 43,200원 | 5,400 | 9,000 | 14,400 |
| 영등포 | 4시간 무료, 이후 5분당 150원 | 0 | 1,800 | 7,200 |
| 광교 | 180분 이내 1,000원, 360분 이내 2,000원, 일 최대 5,000원 | 1,000 | 2,000 | 5,000 |
| 인천문학 | 일 정액 2,000원 | 2,000 | 2,000 | 2,000 |

이 값들이 테스트 케이스가 된다. 계산 함수는 순수 함수이므로 규칙과 분을 입력해 금액을 확인한다.

## 4. 상세로 가는 통로

- 주차 줄 전체를 탭 영역(높이 44px 이상, 끝에 `›`)으로 만든다.
- 탭하면 외벽 시트의 **이용 탭 → 주차 섹션**으로 바로 이동하고 섹션을 잠깐 강조한다. 기존 `자세히 ›`는 유지한다.
- 대부분의 이용자는 상세를 열지 않으므로, 한 줄만으로 결정이 되어야 하고 탭은 깊이 보고 싶은 사람을 위한 것이다.
- 시트 안 주차 섹션의 순서: **요금(원문) → 주차장 목록(각각 길찾기) → 참고 → 링크 → 확인일 + 수정 요청**.
- 측정: 주차 줄 탭 수 / 카드 열람 수. 낮으면 한 줄 위계가 충분하다는 뜻이다.

## 5. 주차장 길찾기

- 지금 길찾기는 외벽 위치로 안내한다. 그런데 `주변` 주차장이 따로 있는 외벽이 많다(당고개, 은평, 영등포 등).
- 주차장 목록의 각 항목에 "주차장 길찾기"를 둔다. 이름으로 지도 앱 검색을 여는 방식(좌표 불필요)으로 시작한다. 기존 길찾기의 지도 앱 선택 기억을 재사용한다.

## 6. 외부 링크 (모두의주차장 등)

**v1은 판교 1곳으로만 시험하고, 전용 기능은 만들지 않는다.**

- 업체 이름을 코드에 박지 않고, 데이터에 일반 구조 `parking.links: [{kind, label, url}]`를 둔다. kind: `ticket`(주차권), `lot`(주차장 정보), `notice`(공지).
- 링크는 값이 있을 때만 버튼으로 보여준다. `https`만 허용하고 도메인을 제한한다(기존 `safeUrl` 방식).
- 문구는 사실만 쓴다: "모두의주차장에서 일일권 구매 · 4,000원 (확인일 2026-10-08)". **"싸다"는 현장 요금과 구매 가격을 둘 다 확인한 곳에서만** 쓴다.
- 수수료/제휴가 있으면 반드시 고지한다. 없더라도 특정 업체를 밀어주는 인상이 되지 않게 중립 문구를 쓴다.
- 이용약관과 링크 정책 확인, 링크 깨짐 점검(분기 1회)이 선행 조건이다.

## 7. 데이터 신선도와 갱신 부담

| 방법 | 내용 |
|---|---|
| 주차 전용 확인일 | `parking.checked_at` 추가. 6개월이 지나면 "요금은 바뀌었을 수 있어요" 안내(기존 `staleness`와 같은 방식) |
| 가격을 베끼지 않고 근거를 가리킨다 | 공영주차장 요금은 시설이 공지하므로 `공지` 링크/주차장 검색으로 연결. 우리가 숫자를 계속 최신으로 유지하지 않아도 되게 |
| 우선순위 | 유료 10곳의 요금은 분기에 한 번 점검. 더 큰 일은 "확인 필요" 32곳 채우기 |
| 이용자 확인 | 유료 외벽에서 방문 후 "요금이 맞아요 / 달라요" 한 번 탭(퀵 태그 PRD의 칩 구조 재사용). 확인이 쌓이면 확인일 갱신. 기존 "수정 요청" 폼도 그대로 |
| 일시적 정보는 칩으로 | "오픈 직후 만차"(파주), "15대가량"처럼 시간에 따라 바뀌는 정보는 데이터에 적지 않고 "주차 만차" 칩(유효 3시간)으로 받는다 |

## 8. 데이터 모델 변경 (제안)

`parking`에 선택 필드를 추가한다. 모두 선택이라 기존 데이터는 그대로 동작한다.

| 필드 | 설명 |
|---|---|
| `rate` | 요금 규칙 `{ free_min, first, step, tiers, day_flat, day_max, conditions[] }` (§3.1). 모두 선택. 앱이 필요한 시간의 금액을 계산 |
| `cost` | 규칙으로 표현되지 않는 외벽용 예외 `{ h3, h5, h8, day }`. `rate`가 있으면 무시 |
| `checked_at` | 주차 정보 전용 확인일 `YYYY-MM-DD` |
| `links` | `[{kind, label, url}]` (§6) |

기존 `fee`(원문), `onsite`, `nearby`, `note`, `status`는 그대로 쓴다. `rate`/`cost`가 없으면 카드 한 줄은 비용 토큰 없이 기존처럼 표시한다(점진 적용). 카드 한 줄의 요약 문구는 계산 결과에서 자동 생성한다.

## 9. 단계

1. **P0**: 유료 10곳의 원문 요금을 `rate` 규칙으로 변환·입력 + 계산 함수 + 카드 한 줄 위계 적용
2. **P0**: 주차 줄 탭 → 이용 탭 주차 섹션
3. **P1**: 주차장 길찾기
4. **P1**: `parking.checked_at` + 오래됨 안내
5. **P2**: `parking.links` (판교 시험) / 요금 확인 탭 / 만차 칩
6. **상시**: "확인 필요" 32곳 채우기 (운영자 확인 + 이용자 제보)

## 10. 지표

| 지표 | 해석 |
|---|---|
| 주차 줄 탭률 | 낮으면 한 줄이 충분함, 높으면 상세 요구가 큼 |
| 주차 관련 "수정 요청" 건수 | 정확도 신호 |
| "확인 필요" 외벽 수 | 32에서 감소하는지 |
| "알려주기" 탭 → 제보 전환 | 빈칸을 채우는 효율 |

## 11. 열린 질문
